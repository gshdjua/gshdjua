# MusicHub RAG 50题评测集

`rag-eval-50.jsonl` 基于当前本地 `audio` 表中的7首歌曲制作，用于评估 SQL 精确检索、关键词检索、向量检索、融合排序、上下文理解和证据引用。

## 覆盖范围

- 歌库及类型统计：5题
- 歌名与歌手双向查询：11题
- 出处、简介和缺失字段处理：12题
- 收藏、相似与语义推荐：10题
- 多条件、无结果与防幻觉：8题
- 多轮上下文、换一批和引用：4题

测试没有集中使用单首歌曲：7首歌曲均有独立问题，并包含多歌曲查询、未收录作品和字段缺失等困难样本。

## 字段说明

- `expected_answer`：人工评测时参考的标准答案，不要求模型逐字一致。
- `must_include`：回答必须出现的事实或关键词。
- `must_not_include`：回答不得出现的错误事实、重复推荐或被排除歌曲。
- `expected_audio_ids`：预期召回的歌曲ID；推荐题可能允许命中其中任意歌曲。
- `history`：多轮问题需要提供的历史上下文。
- `notes`：特殊评分规则。

## 建议评分

每题满分2分，总分100分：

1. 检索正确性1分：预期歌曲命中，且没有命中明确禁止的歌曲。
2. 回答正确性1分：满足 `must_include`，不违反 `must_not_include`，不编造缺失字段。

建议另外记录以下指标，但不并入基础分：

- `Recall@5`：预期歌曲是否出现在融合检索前5名。
- `MRR`：第一个正确歌曲的排名倒数。
- 引用正确率：正文引用编号能否对应末尾证据来源。
- 无结果准确率：未收录或字段缺失时是否拒绝编造。
- 换一批成功率：后续推荐是否排除历史已推荐歌曲。

## 混合检索权重

后端使用按意图切换的加权 RRF：

- `FACTUAL`：SQL 4.0、向量 1.0、关键词 1.5。用于出处、类型、简介和歌库事实查询。
- `RECOMMENDATION`：SQL 1.5、向量 3.0、关键词 2.0。用于相似、模糊和换一批推荐。
- `DEFAULT`：SQL 3.0、向量 1.5、关键词 1.0。用于无法归入前两类的问题。

融合公式为 `来源权重 / (RRF_K + 来源内排名)`，同一歌曲在不同来源中的贡献相加后统一排序。每个 `RetrievalResult` 会保留所用权重档案、原始来源分数和各来源的融合贡献，方便根据50题评测结果继续调参。

## Rerank

混合检索完成后，系统会对候选歌曲执行第二阶段重排：

1. 将加权 RRF 融合分归一化。
2. 按问题意图计算歌名、歌手、类型、出处和简介匹配分。
3. 对同时被 SQL、关键词和向量多路命中的歌曲增加可信度分。
4. 组合为最终重排分，再输出 Top-K。

默认最终分为：`0.55 × 归一化融合分 + 0.35 × 元数据匹配分 + 0.10 × 多路命中分`。出处查询会重点提高出处匹配权重，并对未填写出处的候选降权；推荐查询则提高类型、出处和简介的权重。所有参数都可以在 `application.properties` 中调整。

## 低置信度拒答

Rerank 后还会计算独立置信度，避免“排名第一”被错误理解为“结果可靠”。这是必要的，因为即使所有候选都很差，归一化后第一名的融合分仍可能接近1。

置信度公式为：`0.45 × 检索来源质量 + 0.40 × 元数据匹配分 + 0.15 × 多路命中分`。

- SQL分数按精确歌名、歌手和出处命中的分数段归一化。
- 关键词分按100分归一化并限制在0～1。
- 向量分按相似度限制在0～1。
- 事实查询阈值为0.42，推荐查询为0.30，默认问题为0.36。

低于阈值的候选会在进入Top-K之前被移除；如果所有候选都被移除，传给模型的上下文会明确要求拒绝依据本地歌库作答，并提示用户补充歌名、歌手、类型或出处。

## 数据变化注意事项

该评测集对应创建时的本地歌库快照。管理员修改歌名、歌手、类型、出处、简介或收藏数后，应同步更新受影响题目的标准答案，避免把数据库变化误判为系统错误。

## 自动运行评测

评测只调用管理员检索接口，不调用DeepSeek、不产生模型费用，也不会写入聊天记录。

### 管理后台运行（推荐）

1. 使用管理员账号进入管理后台。
2. 点击左侧“检索评测”。
3. 选择Top-K并点击“开始评测”。
4. 页面会显示实时进度、总体指标、分类指标和失败案例，也可以导出完整JSON报告。

### 命令行运行

1. 启动Spring Boot后端和本地向量服务。
2. 双击 `evaluation/run-evaluation.bat`。
3. 输入管理员密码。
4. 等待50题完成，报告会写入 `evaluation/reports/`。

也可以在项目根目录执行：

```powershell
python evaluation/run_retrieval_eval.py
```

常用参数：

```powershell
python evaluation/run_retrieval_eval.py --top-k 5
python evaluation/run_retrieval_eval.py --base-url http://127.0.0.1:8082
python evaluation/run_retrieval_eval.py --username admin
python evaluation/run_retrieval_eval.py --token "已有的管理员JWT"
```

默认不在命令行参数中填写密码，而是运行时安全输入。如果确实需要无人值守执行，可以使用 `--password`，但该方式可能在命令历史中留下密码。

生成两种报告：

- JSON：保留每题完整召回结果、融合分、重排分、置信度和来源证据，适合程序分析。
- Markdown：展示总体指标、分类指标和失败案例，适合直接阅读。

自动统计：

- `Hit@K`
- `Recall@K`
- `MRR`
- `Top-1准确率`
- `无结果拒答准确率`
- `总体案例准确率`
